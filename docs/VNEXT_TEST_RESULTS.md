## 验证方法与界限

Windows GUI 使用自建目标，不向任意用户窗口发送示例。最初跨进程夹具曾在 Emoji 半个 UTF-16 代理项的 TextChanged 中严格 UTF-8 记录失败，弹错抢焦点；修复记录方式后早期完整流程通过。后续暂停组合改为逐键间隔 80 ms 的真实序列，确认不会在 Ctrl/Alt 到达而 Space 未到达时误取消。退出回归用可取消的内部读取委托确定性暂停在两个预读点；生产仍使用真实 Clipboard API。

受限沙箱拒绝剪贴板/SendInput 的尝试不算通过；原生成功结果来自允许正常桌面交互的运行。测试遇到目标切换时正确停止，不为得到绿灯关闭保护或强制保持焦点。新增加的完整 GUI 套件仍应在没有抢焦点软件的独立会话中复跑。

Chromium 为临时扩展副本添加 localhost 权限，生产清单无 host_permissions。弹窗替换剪贴板读取和活动标签查询；其余消息传递与 DOM 输入真实执行。Gecko DOM 的测试替身不验证 Firefox 工具栏授权/真实剪贴板路径，故单列临时安装及待手工检查项。

Linux 测试不调用真实 Niri/wtype。其事件服务器和发送进程为明确替身；socket 本身在 WSL 上实际运行。新开聚焦窗口、查询期间失焦/停止、倒计时边界暂停均有回归，但 compositor IPC 与发送无法原子化这一限制仍然存在。
